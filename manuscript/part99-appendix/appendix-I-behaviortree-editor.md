# 附錄 I. BehaviorTree 編輯器案例（進階）

> 7.2 中討論的 BehaviorTree 編輯器的進階案例。自主開發的決策、實現與運營經驗。

---

## I.1 自主開發的決策

7.2.8 中討論的四項決策依據的詳情。

| 依據 | 詳情 |
|---|---|
| 必須支援 diff·git 追蹤 | UE BT 是 .uasset binary,變更難以追蹤。改用 JSON 後可進行文本 diff |
| subtree 引用 + 影響追蹤 | 運營 100\~300 個 BT 時,以 subtree 為單位的影響分析至關重要 |
| 模擬驗證 | 無需構建即可單獨執行 BT |
| AI 輔助編寫 | LLM 能自然地生成、解析 JSON BT |

---

## I.2 實現階段

```
[1. 策劃·需求定義 (1~2周)]
   - 明確四項需求
   - 設計 JSON 模式
   
[2. 執行時實現 (3~4周)]
   - JSON 解析器
   - BT 執行引擎
   - 解析 subtree 引用
   
[3. 編輯器實現 (4~6周)]
   - JSON 編輯器 (圖形化)
   - subtree 庫 UI
   - 影響分析工具
   
[4. 模擬器 (2~3周)]
   - 單獨執行 BT
   - 提取統計資料
   
[5. AI 整合 (2~3周)]
   - LLM 輔助編寫 BT
   - 上下文注入
   
[6. UE 整合 (2~4周)]
   - 與 UE BT 相互轉換
   - 構建整合
```

總計約 4\~6 個月。開發者 1\~2 人。

## I.3 運營設計與事故防範

### I.3.1 關於運營資料

這款編輯器是處於 R&D 階段的內部工具,並未達到可稱為"一年運營實測"那樣的長期、大規模執行。因此,遵循本書的原則,這裡不刊載任何編造的運營統計資料。I.1 中提到的 100\~300 個的規模,是為自主開發提供正當理由的**設計目標**,而非實測結果。

在設計所設定的限制中,真正寫入程式碼的是 **subtree 引用 depth 5 上限**(防止無限遞迴)。運營中的 BT 數量、模擬執行次數之類的數值會因專案規模而異,因此與其寫下編造的數字,不如在你自己的環境中親自測量。

### I.3.2 運營中防範的事故與經驗教訓

| 事故 | 經驗教訓 |
|---|---|
| subtree 無限引用（遞迴） | 引用 depth 5 上限 |
| 模擬與實際行為的差異 | 每月校準模擬環境 |
| LLM 輸出 BT 的幻覺 | 加強驗證 + 設計師評審 |
| BT 數量激增（計劃外） | 季度整理週期 |

## I.4 成本·ROI

開發與運營成本是基於製作這款工具時所定日程的估算,而"效果"一側並非實測值,而是引入該工具所要達成的方向。這裡不寫編造的節省數字,只寫方向。

| 專案 | 值 | 性質 |
|---|---|---|
| 開發成本 | 開發者 4\~6 個月 | 計劃日程（估算） |
| 運營成本 | 開發者每季度 1\~2 周（維護） | 計劃日程（估算） |
| 預期效果——運營人力 | 大規模運營敵方 NPC 時,壓縮 BT 負責人員 | 方向（未測量） |
| 預期效果——事故 | 從結構上減少 subtree 遞迴、LLM 幻覺這類 BT 事故 | 方向（未測量） |

引入成本的回收週期會因專案的 NPC 規模與人力成本而異,因此建議在你自己的環境中測量上述各項後再作判斷。筆者不會做出"一年內即可回收"之類的斷言——那個數字我們並不掌握。

## I.5 LLM 輔助案例

### I.5.1 編寫新的敵方 NPC BT

使用 7.2.6 的提示詞。以下是展示輸出結構的示例(並非實際運營資料,而是格式示例)。

```json
{
  "bt_id": "bt_new_mage_v1",
  "category": "ranged_combatant",
  "tags": ["scholar_faction", "ranged", "magic"],
  "root": {
    "type": "selector",
    "children": [
      {
        "type": "sequence",
        "name": "low_hp_retreat",
        "children": [
          {"type": "condition", "fn": "hp_below", "param": 0.3},
          {"type": "subtree_ref", "id": "subtree_retreat_to_ally"}
        ]
      },
      {
        "type": "sequence",
        "name": "magic_attack",
        "children": [
          {"type": "condition", "fn": "enemy_in_range", "param": 15},
          {"type": "subtree_ref", "id": "subtree_magic_attack_pattern"}
        ]
      }
    ]
  }
}
```

設計師評審後進行模擬 → 通過 → 應用到構建。

## I.6 讀者參考

BehaviorTree 的自主開發通常在運營規模達到 100 個以上時才具有正當性（設計判斷）。低於此規模時,使用 UE 自帶的 BT 即可。

備選方案:
- BehaviorTree.CPP（開源、標準）
- Behavior Designer（外部商用）
- 自主開發（自由度最高,運營負擔大）

選擇標準參見 7.2.8。
